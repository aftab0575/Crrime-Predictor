Dataset

Schema, location, and active file behavior

Datasets are tabular CSV files under data/ (for example data/pakistan_crime_dataset_1000.csv). Each row is one incident-like record: where it happened ( Province, City), timing ( Hour, Month), Weapon_Used, descriptive fields such as Crime_Type, and the high-level label column Crime_Category used as the prediction target. Column layout must stay consistent with scripts/train.py so training and the web form remain aligned.

City bucketing

Only the most frequent city names are kept as-is; rarer cities are grouped (e.g. Other) so inference uses the same encoding as training. After you train on a CSV, the dashboard and prediction UI use that file as the active dataset—or the default at startup if you have not retrained in the app.

Model training

Algorithms, outputs, and where artifacts live

Training compares Random Forest and Logistic Regression to predict Crime_Category from province, city bucket, hour, month, and weapon. The stronger model on a held-out test split is saved as models/crime_pipeline.joblib, with crime_label_encoder.joblib mapping numeric outputs to category names.

Run python scripts/train.py or use the in-app Train page on localhost only—do not expose training on the public Internet.

What prediction means

How to read the Predict page and confidence bars

The Predict page does not forecast whether a crime will occur or assign legal charges. It answers: given your inputs, which Crime_Category label in the training data receives the highest model score? Categories are coarse groups defined in your CSV (for example Violent, Property, Cyber, Drug—the exact set depends on the file you trained on).

Estimated confidence

Values reflect predict_proba—how the model distributes weight across labels for that single input row. They are not real-world crime odds or survey-based location risk; they show how strongly the classifier prefers one category over others in this academic setup.

Limitations

Scope and responsible use

Results are illustrative for coursework: they depend on dataset quality, temporal coverage, and simplified features (no external social-media feeds in this build). Broader thesis discussion may reference literature on events and social data as future work. The optional Assistant page uses Google Gemini with an automatic aggregate summary of the active CSV (counts and top categories), not verbatim row dumps sent to the model.
